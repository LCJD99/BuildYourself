# BuildYourself · 长期目标进程管理规格 v0.1

本规格整合 [MVP PRD v0.1](MVP-PRD-v0.1.md) 和 Q1–Q39 的讨论。原 PRD 中与后续决定一致的要求纳入 MVP 基线。本轮原型按两阶段验收，后续明确调整的条款采用新的口径。暂缓事项和待定口径列在文末。

## 问题陈述

我可能同时推进学习、训练和项目交付，但最开始只知道「我想学英语」这样的方向。即便有了待办，也很难知道任务为什么值得做、临时承诺会挤掉什么，以及完成了很多行动以后，能力或长期目标究竟有没有进展。

我需要从自然语言意图开始，形成能执行、能复盘的目标计划。新承诺出现时，我需要知道哪天做什么、原计划会怎么变、还有什么确实排不下。做完以后，我需要用反馈分别判断交付是否通过、长期目标是否推进，并知道下一步要做什么来验证或改善结果。

产品面向同时推进多个长期目标、愿意行动并提供基本证据的人。典型用户既有课程或项目等外部截止，也有长期能力目标，且受时间、精力或恢复资源限制。首版不限年龄、职业和目标领域，优先解决跨目标协调。只需要普通提醒、完整会议日程或专业诊断的人群不作为首批重点。

## 解决方案

BuildYourself 用个人执行知识图谱保存目标、计划、行动、证据和关系。用户先在 pi 表达意图，核对 Agent 提议的目标、里程碑、近期行动和证据要求。系统把确认后的任务安排到天。执行后，用户提交一条文本反馈，同一份证据可按各自标准用于交付验收和长期进展评价。用户能在应用里查看判定和依据，并从周复盘接受一项可验证的后续行动。

应用原型按单用户、本地运行设计。用户先在 pi 中录入和核对，回浏览器应用查看状态。应用打开后先展示今天的关键行动，随后可沿三栏查看节点及里程碑。个人执行图谱提供权威状态，领域知识提供可参考的方法和评价依据，规则和查询给出可复现的判定与数值，Agent 负责理解、起草、解释和生成 HTML 图表。

## 用户故事

1. 作为有长期意图的用户，我希望能用「我想学英语」这样的话开始，以便在想清细节前就能进入规划。
2. 作为刚开始规划的用户，我希望 Agent 只补问会改变计划的关键信息，以便把意图落实到一个场景和可观察的结果。
3. 作为说不清当前水平的用户，我希望把一次基线练习作为首个行动，以便用实际反馈决定接下来的练习。
4. 作为创建目标的用户，我希望一次核对成功描述、里程碑、近期行动、证据要求和复盘周期，以便确认计划反映我的意图。
5. 作为尚未想清成功条件的用户，我希望保存草稿，以便稍后完善目标并纳入规划。
6. 作为目标领域没有专用模板的用户，我希望仍能用通用模板建目标，以便管理自己真正想做的事。
7. 作为推进长期目标的用户，我希望近期行动具体、后续阶段先保留里程碑，以便执行一段时间后按反馈细化。
8. 作为拟定里程碑的用户，我希望 Agent 先评估标准是否合理、证据是否可获得，再由我核对，以便日后按同一标准判断。
9. 作为并行推进多个目标的用户，我希望查看活跃目标和下一里程碑，以便决定把注意力放在哪里。
10. 作为需要调整目标组合的用户，我希望能暂停、完成或归档目标，以便释放活跃名额并保留历史。
11. 作为自行维护计划的用户，我希望手动增加或编辑目标相关任务，以便记录 Agent 尚未掌握的行动。
12. 作为接到新承诺的用户，我希望直接粘贴通知或描述任务，以便快速整理交付物、截止日期、预计耗时、依赖和验收条件。
13. 作为核对新承诺的用户，我希望看到 Agent 不确定的字段，以便在确认前纠正关键事实。
14. 作为收到新承诺的用户，我希望先确认并保存承诺，再决定是否采用推荐重排，以便独立处理事实和安排。
15. 作为拒绝重排的用户，我希望保留新承诺和原计划，并看到新承诺尚未排入，以便之后继续处理。
16. 作为有临时外部承诺的用户，我希望把暂时没有目标归属的承诺放进「杂项」，以便让它占用计划容量。
17. 作为只想知道哪天做什么的用户，我希望看到日级计划和预计耗时，以便自行决定当天的具体执行时刻。
18. 作为首次使用规划的用户，我希望可以直接按默认每天 4 小时生成计划，以便无需预先填容量就能开始。
19. 作为某天实际可用时间有变化的用户，我希望修改当天容量，以便让建议反映真实约束。
20. 作为要做较大任务的用户，我希望核对 Agent 提议的子任务，以便把有明确完成条件的行动排到不同日期。
21. 作为面对多个目标和截止日期的用户，我希望看到一份可执行的推荐安排和变化原因，以便知道哪些任务顺延及其影响。
22. 作为截止前容量不足的用户，我希望看到可排的部分和剩余时间缺口，以便决定如何处理未排入的工作。
23. 作为反复查看计划的用户，我希望计划在没有触发条件时保持稳定，以便按已确认的安排执行。
24. 作为每天打开应用的用户，我希望先看到今天的关键行动，以便马上开始。
25. 作为需要看行动来由的用户，我希望点击行动后能看到它所在的位置和关联的里程碑，以便理解它推动什么。
26. 作为浏览目标结构的用户，我希望左侧像文件导航一样切换节点，中间看到当前层和下一级，以便知道自己在看哪里。
27. 作为切换节点的用户，我希望右侧同步切换里程碑视图，以便看到当前目标、项目或任务对应的进展。
28. 作为使用共享项目的用户，我希望可以从其他目标进入同一个项目，以便从不同目标查看同一份任务与证据记录。
29. 作为操作证据的用户，我希望先在 pi 中提交和核对文本反馈，再回应用看结果，以便用一条反馈完成记录和复盘。
30. 作为需要复用证据的用户，我希望从任务或里程碑录入时默认关联当前对象，也能手动补充其他关联，以便只提交一次。
31. 作为刚完成行动的用户，我希望看到执行已完成、证据是否足够两个结果，以便知道勾选完成后还有什么要补。
32. 作为提交交付反馈的用户，我希望同一份证据能分别用于交付和里程碑评价，以便理解交付通过为何仍可能没有达到长期标准。
33. 作为检查进展的用户，我希望区分证据不足和完整实测未达标，以便知道该补测还是改练习。
34. 作为查看判定的用户，我希望看到用过的标准、反馈来源和证据缺口，以便核对结果。
35. 作为需要确认能力进展的用户，我希望先看到判定依据，再完成规定的确认，以便决定何时正式记为达成。
36. 作为达成里程碑的用户，我希望看到一个简短动画，以便知道状态刚刚更新。
37. 作为发现证据理解错误的用户，我希望只纠正一次证据，系统就重新判定所有引用对象，以便避免各处结果不一致。
38. 作为回看旧复盘的用户，我希望看到证据已更正的标记并能打开最新判定，以便了解当时的结论和当前结果。
39. 作为查看进展视图的用户，我希望图表基于实际证据，只有单次观察时直接显示该观察，以便避免把单点误读为趋势。
40. 作为回顾执行的用户，我希望从只读历史日历按日期查看实际活动和证据，以便回查过去发生了什么。
41. 作为做周复盘的用户，我希望区分交付结果、能力进展和证据缺口，以便看清本周的投入带来了什么。
42. 作为准备下一周的用户，我希望复盘只推荐一项可验证的调整，并说明预期结果和验证时间，以便知道该采取什么行动。
43. 作为接受复盘建议的用户，我希望系统创建一条关联里程碑的任务，并在下次复盘回查任务和证据，以便知道调整是否实际发生、结果如何。
44. 作为用 Agent 协助计划的用户，我希望重大变更按要求由我确认，以便掌握目标标准、外部承诺和关键取舍。
45. 作为管理多个目标的用户，我希望在组合总览用一致的字段比较各目标的状态、近期证据和风险，以便决定继续、调整或暂停哪些目标。
46. 作为进入单目标工作区的用户，我希望不同类型的目标有一致的信息结构，以便快速找到下一行动、近期证据和复盘入口。
47. 作为打开行动详情的用户，我希望同时看到截止、依赖、完成标准和最近变更，以便理解它为什么这样安排。
48. 作为浏览目标和详情的用户，我希望能从总览直达目标并在返回时恢复浏览位置，以便继续原来的操作。
49. 作为查看项目进度的用户，我希望在适合当前数据的视图之间切换，以便从不同角度看同一份进展。
50. 作为回看某个目标的用户，我希望能按目标筛选历史日历并打开当天的证据和复盘摘要，以便核对一段时间里的投入。
51. 作为资源有限的用户，我希望知道不同目标之间哪里有冲突、哪里能共享材料或活动，以便做出可解释的取舍。
52. 作为需要纠正记录的用户，我希望能手动编辑目标、任务、证据和关系，以便掌握自己的计划与评价依据。
53. 作为已有外部日历的用户，我希望可以选择用它校准容量，并在系统写回前确认，以便控制外部日程如何参与计划。
54. 作为与 Agent 对话的用户，我希望始终看到它当前在讨论哪个目标或任务，以便核对建议适用的对象。

## 实现决策

### 权威状态与权限

- 原型由本地浏览器应用和 pi 组成，两者共用一份本地权威数据。pi 是原型阶段的 Agent 业务入口。应用内对话入口留待证据链跑通后设计。
- 个人执行图谱是权威状态，页面从图谱和规则结果读取数据。聊天记录或向量检索只提供辅助上下文。领域知识图谱记录产品支持的目标和活动类型、适用方法、评价标准、证据要求、常见约束、依赖与冲突，以及外部来源、适用条件和版本。原型先用通用规划模板，MVP 提供学习、健身和项目型深度模板，其他领域沿用通用模型。
- 图谱关系包括归属、依赖、贡献、衡量、约束、竞争、协同及替代。推断中的关联标为「验证中」。每条推断关系记录来源（用户确认、规则、专业资料或 AI 推断）、可信状态（候选、已确认、已验证或已否定）、证据引用、创建时间、版本和最后更新时间。候选关联经用户核对后才可成为确认关系。AI 推断不能直接作为事实或用于高影响重排。
- 单一上下文 Agent 负责理解输入、抽取候选对象、提议关系、澄清缺失字段、解释计算结果和提出一次具体调整，记录用户确认、拒绝或修改的原因。规则引擎计算交付、阶段、趋势和风险，检测跨目标与跨项目冲突。规划器校验硬约束，生成一份推荐。
- 图谱写入经过结构校验、实体对齐、规则检查及必要的用户确认。允许 Agent 自动生成内部计划草稿、提出候选关系、更新任务执行状态和生成复盘草稿。PRD 允许低影响的低优先级任务移动，但新硬承诺触发的推荐重排仍按双确认流程执行。写入外部日历、改变目标或标准、取消外部硬承诺、重大资源取舍、确认高置信度能力进展以及确认候选关系均须用户确认。
- 状态变更保存到事件日志。规则、目标契约、评价标准和重大计划调整均需版本化。标准变更从新版本生效，历史进度按当时适用的标准保留。证据更正可以更新当前判定，已完成的周复盘保留当时的内容并附更正标记与最新判定入口。
- 建议可追溯到目标、证据、关系或规则。呈现时区分事实、推断和建议。用户可纠正 Agent 的提取结果，确认、拒绝或修改重大变更，并手动编辑目标、任务、证据与关系。原始图谱编辑器作为高级功能。

| 实体 | 业务定义 |
|---|---|
| 目标（Goal） | 至少持续 4 周，可拆成里程碑，并具有成功描述。 |
| 项目（Project） | 围绕目标组织的工作包，一个项目可服务多个目标。 |
| 承诺（Commitment） | 有责任方、范围或截止时间的外部或内部承诺。 |
| 任务（Task） | 可执行行动。归属活跃目标或项目，符合条件的外部承诺可归入杂项。 |
| 里程碑（Milestone） | 可验收的阶段性结果。 |
| 能力（Capability） | 用户需要长期提升的能力。 |
| 证据（Evidence） | 支持判断任务完成、能力变化或目标进展的材料和数据。 |
| 约束（Constraint） | 时间、精力、恢复、资源或外部规则等限制。 |
| 干预（Intervention） | 系统或用户采取的一次调整。 |
| 复盘（Review） | 对一段时间内执行、结果和关系的回顾。 |

### 从自然语言意图形成计划

- 用户可以从一句泛化意图开始。pi 先问清想在什么场景做到什么、已有基础和关键限制。对会改变路径的未知项先澄清，当前水平不清楚时可以提议一次基线行动。
- pi 根据用户输入和通用模板起草目标、里程碑、第一批具体行动、约束、证据要求、复盘周期及候选关系，并评估里程碑标准是否合理、可观察、可核对。用户编辑或核对后，系统把通过校验的对象及关系写入图谱。近期行动先明确，后续阶段可保留在里程碑层，拿到反馈再细化。
- 目标契约包含成功描述、至少一项可观察的结果、能力表现或交付证据，以及复盘周期。未满足时保存为草稿，退出自动规划和监督。生命周期包含草稿、活跃、暂停、完成与归档。系统应支持最多 10 个活跃目标，达到上限后须先暂停、完成或归档一个。暂停、完成和归档不限数量。完成须满足证据条件并由用户确认。风险是派生提示，容量不足时明确提示。暂停目标保留历史并退出日级规划，放弃或归档记录原因。
- 已确认的行动进入待排任务池。日级规划器接收明确的任务和约束，依据日期级容量生成计划。自然语言目标到结构化计划是独立且必须验收的一步，不能用预置任务替代。

### 外部承诺与日级计划

- 外部承诺先提取交付物、截止日期、任务、预计耗时、依赖、验收要求和归属。用户核对并确认承诺后保存；系统再展示容量影响和一份推荐重排，供用户单独确认或编辑。用户拒绝重排时保留承诺和原计划，显示承诺尚未排入。
- 任务通常归属活跃目标或项目，用户可手动添加目标相关任务，并配置完成标准和证据要求。「杂项」是暂时没有目标归属的外部承诺的例外入口。杂项参与日级安排并占用容量，独立于 10 个活跃目标名额和目标进度统计。此规则更新 PRD §8.5 和 A02 的适用口径。
- 周计划是基线，每天提供一份具体待办，展示日期、优先级、预计耗时、归属和关联里程碑。系统可以突出少量关键行动，数量无产品硬上限。计划粒度到日，具体执行时刻由用户决定。默认每天 4 小时，可按天修改；使用默认值时注明按默认容量估算。
- 按本轮对 Q9 的口径，规划器可以把已有子任务分配到不同日期。需要拆分新任务时，由 Agent 提议，用户核对后再排。规划需校验容量、硬截止和依赖，在同样输入下保持稳定，并尽量少改原计划。软优先级和冲突排序的具体算法仍待定。
- 新硬承诺、截止或范围变更、容量或约束变化、用户指出计划不可执行、重大执行偏差可以触发重排。日常打开或刷新页面沿用已确认的计划。推荐说明改了什么、顺延了什么和原因；用户可以直接修改，变更进入事件记录。
- 跨目标关系聚焦时间、精力和恢复冲突、前置依赖、能力贡献、共享材料或活动、资源替代。每条可见关系应说明它影响的判断或行动。计划调整流程突出少量与当下决策有关的冲突或协同，其他关系可以在工作区和复盘中回看。
- 重排优先保护硬截止和恢复约束。若移动可顺延事项后仍排不下，保留承诺和硬截止，给出容量内的一份安排，标明未排入的事项和时间缺口。需要牺牲或延期硬承诺等重大取舍时由用户决定。

### 文本证据、评价与周复盘

- 原型先支持文本反馈，记录原文、来源、时间和关联对象。从任务或里程碑发起录入时默认关联当前对象，用户可手动关联其他对象。证据只保存一次，每个对象独立按自己的标准判定。自动推荐关联作为后续算法重点。
- 任务和里程碑可以配置最低证据等级。E0 为无需证据，只反映执行状态；E1 为用户自报，默认低可信度；E2 为可验证产出，默认中可信度；E3 为外部专业反馈，默认高可信度。文本是本轮的录入形式。执行完成可独立记录，自报可以反映体验与目标意义。关键里程碑的高置信度进展至少需要符合要求的 E2 或 E3 证据。
- 目标契约定义成功条件，硬性外部要求约束交付，外部反馈可用于修正能力判断。可量化条件由规则核验；定性条件由 Agent 汇总证据和理由，按确认要求处理。Agent 要能区分「材料不完整，无法判定」和「材料完整，本次未达标」。
- 多源评价按目标契约、结果与能力指标、外部标准与专业反馈、执行数据、现实应用与迁移分层。完成率、时长、负荷和频率反映执行过程，真实展示、比赛、作品或工作表现用于验证应用。交付型关注里程碑、质量和验收；学习型关注掌握、留存、迁移和真实输出；健身型关注表现、能力趋势、负荷和恢复；通用型关注结果证据、自评和现实场景验证。
- 同一张结果卡分别展示交付和长期进展的结论、依据及证据缺口。原型按任务结果与里程碑分别评价来验收。进展判定达到标准后，凡 PRD 要求确认的，由用户确认后才记为达成并播放简短动画。
- 用户在证据详情纠正记录时，系统重新判定所有引用它的对象，并让用户看到哪些结果变了。图表和当前状态随新判定更新，历史复盘按前述规则标记更正。
- 周复盘区分真实进展与单纯的执行投入，检查偏差可能来自计划、方法、精力、外部事件或证据不足。区分事实和待验证推断，围绕一个关键变量提出一项具体调整，说明预期结果和验证时间，并记录用户确认或修改。缺测量时建议补测，完整实测未达标时才有依据建议调整做法。用户接受建议后创建关联里程碑的行动任务，纳入后续计划；下一次复盘区分未执行、已执行但缺证据，以及已有可判断的结果。

### 三栏应用与 HTML 呈现

- 左侧是文件导航式树，中间展示当前层及下一级节点，右侧跟随当前节点展示里程碑 HTML。共享项目有一个主要位置，其他目标通过关联入口打开同一项目。切换节点时三栏保持对应关系。
- 默认打开「今日关键行动」。点击行动后，左侧定位归属，中间进入对应层级，右侧展示当前节点的里程碑。冲突在后续计划调整流程中处理，首页优先帮助用户开始今天的行动。
- 保留三个信息层级。目标组合总览用统一摘要呈现各活跃目标的状态、下一里程碑、最近证据和风险，支持跨目标比较；详细任务、图表和完整日程不堆在总览。单目标工作区有固定信息结构：目标地图、当前进度、里程碑与承诺、近期证据、下一行动、复盘入口。行动与证据详情展示归属、截止、预计耗时、依赖和冲突、完成标准、证据要求、最近变更及 Agent 建议，优先使用抽屉或弹层保留浏览上下文。
- 面包屑展示当前位置。用户可从总览直接进入目标，返回时恢复筛选、滚动位置和选中节点。MVP 应用内 Agent 采用一个可展开入口，显示当前讨论对象，并根据所在层级提供上下文。原型先使用 pi，应用内入口的具体位置和交互后定。
- 项目类型提供默认视图，用户可以在符合数据语义的视图间切换。Agent 在受控视图范围内选择并生成 HTML 图表和说明，规则或查询提供数据、判定和进度。图旁显示证据数量、来源、最后更新时间及置信状态。数据不足时保留当前视图的评价语义，明确提示证据缺口；只有一次观察时展示观察值和可支持的结论。近似进度显示离散状态或规则计算的区间。

| MVP 视图 | 适用数据与约束 |
|---|---|
| 进度条 | 交付物固定、分母明确。 |
| 阶段／里程碑图 | 能力成长和阶段结果。 |
| 趋势图 | 多次可比较的指标与结果变化。 |
| 关系树／图谱 | 目标结构和跨项目关系。 |
| 饼图／环形图 | 可表示进度区间及证据状态，或时间、活动和资源构成。同一图只采用一种语义。 |
| 历史日历热图 | 实际执行和证据分布。 |

- 只读历史日历展示当日涉及的活跃目标、已完成的目标相关活动和证据标记，支持按目标筛选，并在点击日期后显示当天证据和复盘摘要。日历只用于回查，不用于建任务或调整计划。杂项和普通外部日程不进入目标历史日历。
- 用户可选择导入外部日历，仅用于判断可用容量。外部日程默认不在产品中展示，也不进入目标统计或交付物。写入或修改外部日历须用户确认。本轮原型用默认容量和手动修改完成验收。

## 测试决策

当前工作区以需求文档为主，尚无可复用的应用入口、自动化测试或 ADR。以产品外部入口作为主验收边界，从 pi 提交自然语言或反馈，在浏览器应用核验保存的对象、计划、证据和图表。规则层的验证聚焦可见契约，如相同输入的计划结果、容量是否超限和同一证据的独立判定。HTML 检查内容、对应节点及证据引用，生成文案或标记无需逐字一致。

| 阶段 | 场景 | 可观察的通过标准 |
|---|---|---|
| 第一阶段 | 用预置目标、任务、里程碑，在 pi 提交一份文本反馈 | 证据只存一份，可手动关联多个对象。右栏展示「交付已验收」及独立的里程碑结果，能指出证据不足或本次未达标的原因。 |
| 第一阶段 | 切换节点，检查判定、确认和更正 | 右栏跟随选中节点。证据不足与实测未达标可区分。需确认的结果在用户确认后才记为达成并播放动画。纠正一份证据后，所有引用它的当前结果更新。 |
| 完整原型 | 从空白状态说「我想学英语」或等价意图 | pi 能澄清场景和预期结果，必要时提出基线行动，生成可编辑草稿。确认后形成可浏览的结构化目标、里程碑、行动和证据要求，近期行动进入日级计划。无需录音即可走完流程。 |
| 完整原型 | 多个活跃目标下收到新的硬承诺 | 用户可先确认承诺再确认重排。计划按天校验容量，默认每天 4 小时且可修改。只给一份推荐并解释变动；拒绝推荐时保留承诺和原计划，标出尚未排入。 |
| 完整原型 | 跨目标容量不足，或新承诺放入「杂项」 | 超出容量时保留硬截止，列出时间缺口和未排入事项。「杂项」消耗容量且不计入目标名额与进度。相同状态下刷新页面得到相同计划。 |
| 完整原型 | 每日执行、历史回查与周复盘 | 首页先展示今日关键行动，点击后正确定位三栏。实际行动和证据可从只读历史日历回查。接受一项复盘建议会创建关联里程碑的待办，下次复盘能追踪执行和证据。历史证据更正可从原复盘跳到最新结果。 |

第一阶段的预置数据用于先验收证据链，完整原型以从自然语言意图到日级行动、证据与周复盘的闭环为准。MVP 端到端验收覆盖三个并行活跃目标。可使用英语课程、长期健身与项目交付的组合，也可用等价场景。输入一条新的外部承诺，识别归属与容量影响，生成一份日级调整。执行目标相关任务后录入不同等级的文本证据，覆盖「只完成行动」「已有证据但尚未达标」和「满足证据门槛」三类情形。检查进度区间或离散状态、证据置信度、不同项目的数据视图、只读历史日历和一次周复盘调整实验。两组不同领域的独立验收暂缓。

核心验收用例可以使用一条项目反馈：「测试报告已按要求提交，完整基准测试测得延迟 230 ms。」当交付要求是提交报告、里程碑标准是延迟低于 200 ms 时，同一条反馈可以分别支持「交付已验收」和「本次实测未达标」。如果反馈只说报告已提交，仍可判断交付，里程碑则应指出缺少哪项测量。

计划用例可以从本周原计划容量充足开始。用户收到一条通知，要求周三前提交大纲、周五前交成果。系统保留两个截止，说明会顺延哪些既有活动。另测项目交付和训练在同一天争用容量的情况，推荐应保护硬截止和恢复约束；两者无法同时满足时，明确提示用户决定取舍。

| 编号 | MVP 验收项 | 通过标准 |
|---|---|---|
| A01 | 活跃目标上限 | 可创建至 10 个活跃目标。暂停、完成、归档不计入。 |
| A02 | 今日待办归属 | 任务关联活跃目标、项目或符合条件的杂项。 |
| A03 | 权威状态 | 页面根据图谱和规则结果展示，清空聊天上下文后仍可读取已保存状态。 |
| A04 | Agent 写入权限 | 须确认的高影响变更在用户确认前不生效。 |
| A05 | 计划稳定性 | 没有重排触发条件时，重复打开页面得到同一份计划。 |
| A06 | 单一推荐 | 每日只给一份推荐安排。 |
| A07 | 临时任务重排 | 按日期比较计划，只调整必要事项，并解释变化原因。 |
| A08 | 完成与进展分离 | 仅勾选任务完成时，能力或目标进展不自动提高。 |
| A09 | 进度可信度 | 模糊进度同时显示证据来源、数量、最后更新时间和置信状态。 |
| A10 | 只读历史日历 | 只能查看实际活动和证据，不能从中排期或创建任务。 |
| A11 | 可复现可视化 | 相同数据与规则给出一致的图表数值和判定。 |
| A12 | 推断关系可信度 | AI 提出的关系显示来源、置信状态和候选标记。 |
| A13 | 标准版本 | 新标准生效后，旧进度仍按当时的标准保留。 |
| A14 | 稳定的信息层级 | 三栏支持目标组合、单目标、行动与证据详情的切换，返回时恢复浏览状态。 |
| A15 | 单一 Agent 上下文 | 系统显示当前讨论对象，产品只有一个 Agent。原型在 pi 中核对当前对象，MVP 再验收应用内入口。 |

## 范围之外

- 原型阶段暂缓自动推荐跨对象证据关联、录音等媒体证据、深度领域模板和跨领域双用例验收。首批试用者选择留到集成测试阶段讨论。
- 正式平台形态、账号与多设备同步、新用户引导细节、通知与提醒、首批外部日历与数据接口、数据存储和保留政策、导出与删除、健康数据授权与隐私、详细状态机与异常状态、性能和容量 SLA 留待后续产品、技术及合规评估。相关能力进入实现前须明确这些决策。
- MVP 保持单用户。完整日程排期与会议管理、拖拽日历、通用待办收件箱、AI 教学与课程内容生成、课程市场、多人协作、教练账号、社交和排行榜均在范围之外。产品只呈现可解释的目标进展，专业医疗、康复、营养和心理诊断、替代专业教练、任意图表生成以及 Agent 自行改变目标标准也不在范围内。健康相关建议应明确产品能力边界。「杂项」仅作为暂时无目标归属的外部承诺入口。

| 指标组 | 观测项 |
|---|---|
| 输入与理解 | 通知与任务字段提取正确率、字段修正率、Agent 提议的目标与关系被确认或否定的比例。 |

| 证据与进度 | 目标相关任务附带证据的比例、单条证据记录耗时、进度是否可追溯到证据、用户是否理解执行完成与能力进展的区别。 |
| 长期价值 | 四周后仍在维护至少一个目标的比例、周复盘完成率、用户能否发现无效投入或真实进展、下次出现新任务时是否愿意继续使用。 |

使用时长、生成字数和任务数量不作为主要成功指标。
