# BuildYourself · 长期目标与行动管理规格 v0.2

## 问题陈述

用户希望长期推进学习、锻炼或个人项目等目标，但最初往往只能描述一个方向，还需要明确目标、期限和其他约束。目标确定后，用户需要知道近期每天应该做什么，也需要理解行动如何推动目标，而不是只看到一个待办列表。

用户可能同时推进多个长期目标，也可能在计划之外做了有帮助的事情。用户希望用自然语言告诉 Agent 自己做了什么，由 Agent 判断行动完成情况及其对目标属性的贡献。每周结束时，用户希望回顾实际情况，表达对计划的意见，再确认下一周的安排；未完成的行动应自然延续。

## 解决方案

BuildYourself 以长期目标、目标属性和行动组织用户的成长过程。用户通过与 Agent 多轮对话明确目标和约束，核对目标及其属性；目标确认后，Agent 生成一周行动规划。目标可以有多个属性，每个属性有自己的进度；行动和属性是多对多关系，同一行动也可以关联多个目标。

用户每天查看来自多个目标的行动，不需要系统安排当天具体执行时刻。用户用自然语言反馈行动完成情况，Agent 评估行动的完成度与置信度，给出简短反馈，并评估行动对相关属性的贡献。计划外做的事情也可以告诉 Agent：有属性收益的记录为计划外行动及相应贡献，没有收益的记录放入杂项。

每周复盘先总结本周工作，再收集用户对本周和下周规划的意见，生成可通过自然语言调整的下周规划，供用户确认。本周未完成的行动本身延续到下周，与其他下周行动同等对待。

本规格侧重后端业务逻辑、持久化和供前端调用的接口。前端由前端团队负责，具体界面形态不在本规格中确定。Agent 的算法细节可以后续打磨，但其业务输入、评估结果和状态变更需要有明确边界。

## 用户故事

### 目标与属性

1. 作为用户，我希望用自然语言描述长期目标，以便从已有想法开始。
2. 作为用户，我希望 Agent 多轮询问影响目标的关键约束，以便把模糊意图梳理清楚。
3. 作为用户，我希望说明目标期限，以便 Agent 在明确的时间约束下规划。
4. 作为用户，我希望说明具体目标和其他约束，以便目标反映我的实际需求。
5. 作为用户，我希望在启用前核对 Agent 整理的长期目标和属性，以便纠正理解偏差。
6. 作为用户，我希望确认后目标才生效，以便掌握最终目标内容。
7. 作为用户，我希望一个长期目标有多个评估属性，以便分别观察不同维度的成长。
8. 作为用户，我希望查看每个属性的进度，以便了解各维度的变化。
9. 作为用户，我希望从某个属性查看贡献过该属性的行动，以便理解进度来源。
10. 作为用户，我希望一个行动可以贡献多个属性，以便同一次行动的不同收益都能体现。
11. 作为用户，我希望一项行动可以关联多个长期目标，以便共同推进目标的行动只记录一次。
12. 作为用户，我希望同一个属性可以由多项行动推进，以便反映持续积累。

### 每周规划与每日安排

13. 作为用户，我希望目标确认后获得一周的行动规划，以便知道近期如何开始。
14. 作为用户，我希望一次查看一周的规划，以便专注近期行动。
15. 作为用户，我希望规划行动归属于相关长期目标，以便理解行动的目的。
16. 作为用户，我希望一天的行动可以来自多个目标，以便集中查看当天要做的事。
17. 作为用户，我希望每日安排只指出日期和行动，以便自行决定具体执行时刻。
18. 作为用户，我希望按月快速看到哪些日期有行动，以便浏览安排分布。
19. 作为用户，我希望选择一天后查看当天行动，以便了解具体要做的事。
20. 作为用户，我希望查看行动所属目标和相关属性，以便了解行动与长期成长的联系。
21. 作为用户，我希望未完成的行动延续到下一周，以便已有行动不会因为周次变化而丢失。
22. 作为用户，我希望延续的行动在下一周与其他行动同等对待，以便用一致方式查看和反馈。

### 行动反馈与属性贡献

23. 作为用户，我希望用自然语言告诉 Agent 完成了什么，以便无需通过直接点击完成来记录执行。
24. 作为用户，我希望 Agent 判断计划内行动的完成情况，以便记录真实执行进度。
25. 作为用户，我希望看到行动的完成度，以便区分部分完成与完成。
26. 作为用户，我希望看到 Agent 对行动评估的置信度，以便了解这次判断的把握程度。
27. 作为用户，我希望行动记录包含我的反馈和 Agent 的简短反馈，以便回看评估上下文。
28. 作为用户，我希望行动的完成度和置信度共同影响属性贡献，以便属性进度反映行动评估结果。
29. 作为用户，我希望部分完成也可以产生贡献，以便已发生的投入得到体现。
30. 作为用户，我希望同一行动跨周继续执行时不会重复计入已有贡献，以便属性进度不被重复累加。
31. 作为用户，我希望用自然语言报告计划外做的事情，以便记录规划之外的实际行动。
32. 作为用户，我希望 Agent 判断计划外事情是否对目标属性有收益，以便只把有收益的部分计入成长。
33. 作为用户，我希望有收益的计划外行动关联相关属性并产生贡献，以便它与目标进度建立联系。
34. 作为用户，我希望没有属性收益的计划外事情放入杂项，以便保留记录但不虚增进度。

### 周复盘与下周规划

35. 作为用户，我希望 Agent 总结本周工作内容，以便回顾实际行动和进展。
36. 作为用户，我希望在复盘时反馈对本周规划的意见，以便说明计划与实际的差异。
37. 作为用户，我希望提出对下周规划的建议，以便新规划反映我的意愿。
38. 作为用户，我希望 Agent 结合复盘与我的反馈生成下周规划草稿，以便先核对再采用。
39. 作为用户，我希望草稿包含本周未完成的行动，以便延续尚未完成的工作。
40. 作为用户，我希望用自然语言调整下周规划草稿，以便逐步修改不合适的安排。
41. 作为用户，我希望确认后下周规划才生效，以便掌控实际安排。
42. 作为用户，我希望回看本周复盘和下周规划，以便理解规划如何形成。

### 后端接口与持续使用

43. 作为前端开发者，我希望通过稳定的后端接口读取目标、属性和进度，以便展示用户的成长情况。
44. 作为前端开发者，我希望通过后端接口按月查询有行动的日期，并按日查询行动详情，以便实现日历与每日视图。
45. 作为前端开发者，我希望通过后端接口提交自然语言反馈和取得评估结果，以便构建 Agent 交互。
46. 作为用户，我希望关闭应用后仍能读取已保存的目标、规划、反馈和复盘，以便持续使用。

## 实施决策

### 核心领域模型

- **长期目标**包含用户意图、经澄清的目标描述与约束，以及多个用于评价成长的目标属性。期限是需要澄清的约束示例，具体约束取决于目标。目标经用户核对和确认后生效，再生成第一周规划。
- **目标属性**属于长期目标并具有独立进度。属性进度来自行动贡献；系统应能追溯属性相关行动及其贡献，而不仅保存一个无法解释的汇总值。
- **行动**可以关联一个或多个长期目标。行动和属性是多对多关系，单项行动可对多个目标下的多个属性产生贡献；同一属性也可以由多项行动贡献。同一项行动只记录一次，跨目标查看时应能识别为同一行动。
- 行动区分**计划内行动**和**计划外行动**：前者由 Agent 在每周规划中提出；后者是用户在规划之外完成并告知 Agent、经评估对目标属性有收益的事情。用户描述的计划外事情若没有属性收益，记录在**杂项**，不产生属性贡献或提高属性进度。
- 未完成行动本身延续到下一周，是下一周的普通行动；不把它替换为另一个仅用于跟进的特殊行动。系统保留各周的安排与实际情况，能够识别延续的是同一行动。

### 规划与查询

- Agent 生成的规划以一周为用户可见单位，包含该周相关长期目标下的行动及其日级安排。一天的安排可以聚合多个目标的行动；不指定一天内的执行时刻。
- 后端提供按月查询的轻量接口，返回指定月份哪些日期有行动；另提供按日期查询的接口，返回当天行动及其目标关联、计划内／计划外来源和可供展示的完成情况。具体路径、字段名和分页方式由实现确定。
- 月度日期标记和单日行动查询均针对行动安排。不能把只包含已发生事件的历史记录接口直接当作安排接口使用。草稿是否在这些查询中展示尚未确定，实现不应将某个选择表述为已确认的产品决定。
- 周规划草稿与用户确认后的规划需要区分。用户可在确认前通过自然语言调整下周草稿；确认后保存生效结果。确认、修改和读取使用同一份持久状态，聊天上下文不是唯一数据来源。

### 行动评估与进度

- 用户以自然语言描述完成情况，由 Agent 评估；直接点击完成不是本规格的行动完成流程。保存用户原始反馈、对应行动、Agent 评估的完成度与置信度、简短反馈，以及相关属性贡献。
- 完成度表示行动完成情况。置信度表示 Agent 对本次评估结果的把握程度，也与用户提供的描述或材料是否明确有关；它不是对用户诚实程度的评分。
- 完成度与置信度共同影响行动对相关属性的贡献。置信度及贡献计算先采用简单方案，不在本规格中预设量表、阈值、权重或具体模型；评估应有可供业务流程保存和读取的结果。
- 允许部分完成产生属性贡献。同一行动跨周继续评估时，暂按仅补充尚未计入的贡献处理，避免重复累加。具体计算方式仍是待讨论事项，不视为最终算法。
- 对计划外事情，Agent 先评估其对目标属性的收益：有收益时建立计划外行动和相应贡献；没有收益时保留在杂项，不增加属性进度。应保留用户反馈和评估结果，支持后续回看。

### 周复盘与 Agent 边界

- 周复盘包括三个连续环节：总结本周工作；接收用户对本周规划及下周规划的反馈；结合总结、用户反馈和未完成行动生成待确认的下周规划。
- 用户可以通过自然语言继续调整草稿，再确认规划。复盘不是仅生成一条改进建议或一条跟进行动；下周规划可以包含多项行动。
- Agent 负责目标澄清与规划、行动完成和属性收益评估、周复盘分析和下周规划生成。具体提示词、模型、算法和收益公式留待后续设计，但后端需保存业务输入和可读结果，供前端读取及后续流程使用。
- 根据已确认的目标和周规划，后端负责维护行动、属性、反馈、评估、贡献、复盘与规划状态。Agent 生成内容和已确认生效内容应可区分。

### 对既有系统的调整

- 里程碑、证据等级制度和外部临时承诺均为废弃概念，应从文档、领域概念和代码中移除，不能继续作为建目标、行动评估、进度或复盘的前提。
- 当前暂不考虑每日容量或基于容量的安排、冲突处理和自动重排。计划粒度为日，不等同于要求这些排程机制。
- 现有与上述废弃概念耦合的 API、数据模型、规则、Agent 工具和测试需要随新业务闭环调整；迁移既有持久数据的具体方案尚未确定，实施前应确认兼容和数据处理方式，不能默认丢弃用户数据。

## 测试决策

- 以用户可观察的业务结果为准，测试接口输入、返回结果、持久状态与跨请求行为，不依赖内部函数调用顺序或 Agent 生成文案逐字一致。
- 以现有后端 HTTP API 为主要验收边界，覆盖目标、属性、行动、月／日查询和周复盘；复用现有接口测试和隔离数据存储的测试方式，在需要时调整或新增接口。
- Agent 在测试边界使用可控评估和规划结果，以验证后端如何保存、关联和呈现结果；Agent 判断质量与算法效果不以固定模拟结果宣称已验证。
- 至少覆盖以下端到端业务情形：
  1. 多轮目标澄清后核对并确认目标，读取目标属性及第一周行动。
  2. 多个目标共享一项行动，行动贡献多个属性；从每个属性查询到正确的行动与贡献。
  3. 从自然语言反馈得到部分完成评估、置信度、简短反馈和属性贡献；重复或跨周评估不重复计入已有贡献。
  4. 计划外事情有收益时产生行动和贡献，无收益时进入杂项且不改变属性进度。
  5. 按月查询行动日期，再按日聚合查询多个目标的行动；月标记与对应单日结果一致。
  6. 复盘汇总本周、接收用户意见、生成并调整下周草稿，确认后读取生效规划；未完成行动以同一行动延续，周历史仍可回看。
  7. 操作后重新读取数据，确认目标、行动、评估、属性进度和复盘不依赖聊天上下文保存。
- 既有围绕旧概念的测试应随业务重构移除或改写；不能仅为了维持旧验收而保留已废弃的领域约束。

## 范围之外

- 前端页面布局、视觉设计和交互实现。
- 里程碑、证据等级制度、外部临时承诺及其专用流程。
- 每日容量、按容量的冲突处理与自动重排，以及一天内的细粒度时刻排期。
- Agent 的最终算法、模型选型、置信度量表、属性贡献公式及其效果评测方案。
- 未经本轮讨论确定的账号、多设备同步、通知和其他平台能力。

## 补充说明

- 本规格是独立的 v0.2 业务基线，完整描述当前已对齐的目标、行动、属性、规划与复盘闭环；旧规格中未在此确认的规则不自动成为本规格要求。
- 行动部分完成并跨周延续时的属性贡献计算已登记为待讨论事项，当前采用不重复计入的暂定方案。
- 月／日查询对未确认规划草稿的可见性、具体接口字段，以及旧数据如何迁移仍需在实现阶段明确；这些未决问题不改变已确定的核心业务逻辑。
