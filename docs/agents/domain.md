# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root defines domain vocabulary.
- `docs/adr/` contains architecture decision records.

Before exploring a topic, read the glossary and any ADRs relevant to that topic. If they do not exist, proceed without prompting to create them; domain-modeling can create them when terms or decisions are resolved.

Use glossary terms consistently in issues, proposals, hypotheses, and tests. If a proposal conflicts with an existing ADR, identify the conflict explicitly.
